MIND DUEL FUSION 3.13.91 — CONOCIMIENTO COMPARTIDO

Este paquete conserva los datos locales y añade una conexión compartida opcional.
Si Supabase no responde, el juego sigue funcionando con sus datos locales.

CONFIGURACIÓN OBLIGATORIA EN VERCEL
En el proyecto de Vercel, abrí Settings > Environment Variables y agregá estas dos variables para Production (y Preview si querés probar previews):

SUPABASE_URL = https://fvyfaldnwwalxfncqwxy.supabase.co
SUPABASE_SERVICE_ROLE_KEY = la Secret/service_role key del proyecto Supabase

IMPORTANTE SOBRE LA CLAVE
- Pegá la clave solamente en Environment Variables de Vercel.
- NO la pegues en el código, en este archivo, en el navegador ni en GitHub.
- No me la envíes por el chat.
- Después de guardar las variables, hacé un nuevo deployment (Redeploy) para que se apliquen.

QUÉ HACE ESTA INTEGRACIÓN
- Consulta personajes, preguntas y afirmaciones verificadas desde Supabase a través de funciones de servidor de Vercel.
- Usa los personajes y las preguntas compartidas como ampliación de los datos locales.
- Cuando en el modo multijugador el Cerebro da una respuesta clara de sí/no a una pregunta reconocida sobre un personaje existente en la base, envía una propuesta a knowledge_claims.
- Las propuestas quedan con status=proposed. No se convierten automáticamente en hechos ni se usan como hechos verificados.
- Hay límites básicos de frecuencia para reducir abuso.

IMPORTANTE
La función de escritura usa las tablas existentes knowledge_claims y match_events. No hace falta volver a ejecutar schema.sql ni repetir la importación. Si la clave Secret/service_role se regeneró desde que se hizo la importación, usá la clave vigente de Supabase en Vercel.

COMPROBACIÓN
Una vez desplegado, abrí tu web y agregá /api/shared-data al final de la dirección. Si está configurado, debe devolver JSON con "ok": true y las listas de personajes y preguntas. No compartas públicamente ese resultado si contiene datos que no quieras divulgar (la respuesta no incluye claves secretas).
